# 下一階段計劃：雲端試行環境

## 目標

把現有本機 MVP 部署至受保護的雲端試行環境，讓 20 位測試學員可在手機及桌面完成「登入、選課、學習、測驗、證書」流程，並由管理員處理課程、點數及測試付款。

## 執行次序

### 1. 固定可部署版本

- 在 GitHub Actions 驗證安裝、型別檢查、建置、單元及整合測試。
- 建置 API、worker 與前端容器，記錄映像版本及回復方法。
- 增加證書下載、背景工作重試及健康檢查的部署後冒煙測試。

完成條件：每次提交均可重現建置；失敗版本不會部署；指定舊版本可重新啟動。

### 2. 建立 DigitalOcean 試行環境

- 在新加坡區建立應用主機、Managed MySQL、私人 Spaces 儲存及備份儲存。
- 以部署環境注入資料庫、JWT、加密及儲存憑證。
- 設定 HTTPS、平台域名、資料庫 TLS、防火牆及只允許所需來源的 CORS。

完成條件：公開網絡無法直接存取資料庫或私人媒體；平台全程使用 HTTPS。

### 3. 接通測試服務

- 驗證 Resend 寄件域名及註冊、重設密碼、證書通知電郵。
- 接通 Stripe 測試模式，驗證成功、取消、延遲及重送 webhook。
- 驗證 Spaces 短效連結、PDF 證書、QR 查核頁及撤銷狀態。

完成條件：測試付款不會重複入點；證書工作失敗後可安全重試；受保護檔案不可跨帳戶存取。

### 4. 準備試行內容與營運設定

- 由營運方確認正式品牌資料、發證機構名稱及證書顯示方式。
- 匯入三門經審核的試行課程與題庫，維持未公開或邀請制。
- 設定測試點數套裝；正式價格及正式付款繼續停用。
- 加入私隱、退款及試行使用條款。

完成條件：管理員可自行更新課程；頁面及證書不宣稱未獲批的 CPD 學分。

### 5. 雲端驗收與小規模試行

- 執行桌面及手機端到端測試，以及 20 位同時活躍學員測試。
- 測試每日備份、還原、工作重試、告警及操作稽核。
- 邀請首批測試學員，收集登入、教材、測驗及證書流程意見。

完成條件：資料損失目標不超過 24 小時、服務恢復目標不超過 8 小時；重大流程問題修正後才擴大試行。

## 開始前所需資料

- DigitalOcean 帳戶及預算上限。
- 試行域名與 DNS 管理權限。
- Stripe 測試商戶帳戶及 webhook 設定權限。
- Resend 帳戶與可驗證的寄件域名。
- 發證機構正式名稱、品牌標誌、私隱與退款條款。
- 三門試行課程的已審核教材與題庫。

## 暫不啟用

正式收費、正式 CPD 學分、病人資料上載及 AI 模型 API 均維持停用，直至各自完成營運、私隱與認可驗收。
